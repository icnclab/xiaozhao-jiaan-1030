# 居督角色測試手冊

更新：2026-11-07。對應 S1／S2；不再預設居督能建立帳號，亦不以主管身分修改他人逐字稿。

先讀 [00 總覽](00_總覽與系統狀態.md) 的 A/B/C/X 門檻。以下互動項目均需 C 門檻，**本輪尚未執行**；在正式 8140／ltc_clean 不登入、不提問、不寫草稿。先用紙上演練（A）核對流程。實際結果統一填 [04 驗收表](04_驗收勾選表.md)，問題填 [05 問題表](05_問題回報表.md)。

## 步驟 1：本人 LINE 登入（04-2）

①操作：以 S1 已有受控綁定從隔離 LIFF 登入，核對 supervisor 及機構；不可用 dev 登入取代真實 LINE。

②預期／通過：顯示 S1 與正確角色／機構；不是 C1 或 D1 的 session。

③失敗／阻擋：綁定／環境未備妥記阻擋；帳號錯配立即停。不要因為主管職稱就跳過角色核對。

## 步驟 2：一般案件查看、處理與回覆（04-9）

①操作：使用 C1 的 R-A 工單。先核對案件代號及「只看指派給我／包含測試帳號建立的案件」篩選；在已允許的隔離操作範圍內由受派 S1 接手、回覆「UAT 假資料：已收到，請依既有計畫，後續由測試居督確認。」；C1 重開同一工單查看。

②預期／通過：列表／詳情／角色範圍一致，狀態及回覆保存；C1 看到同一內容。回覆已保存、通知待送、通知送達分開記，不把 pending 當已送達。

③失敗／阻擋：無既有可操作工單／未受派／私人歷程政策限制則記阻擋，不改角色或強行加權。錯看別機構、保存失敗、明確失敗卻顯示成功記失敗。通知重送與正式推播一律不做。

## 步驟 3：跨居督共享／轉交邊界（04-10）

①操作：先辨認是服務個案 grant、私人歷程 grant，還是一般工單指派。只使用既有隔離 P-A／P-B 及 S1／S2 已預先設定的授權對照：看一筆有權項目與一筆無權項目。新增／撤銷 grant、改派／轉交按鈕只作紙上演練，不實際按下。

②預期／通過：有權可讀，無權不顯示內容或以 403／404 拒絕；服務個案被授權的居督只讀，不能修改／送出他人草稿，亦不能再授權第三人。私人歷程申訴／改派政策待確認時拒絕，不視為必須開放。

③失敗／阻擋：沒有預置授權對照記阻擋；動態授權／撤銷／改派本輪 X，不能因靜態可讀就把整項「授權撤銷通過」。若未授權仍可看私人內容立即停止回報。

## 步驟 4：法規／服務目錄狀態（04-11）

①操作：在隔離審核目錄看 BA／GA09／SC09 metadata，對照一般目錄顯示範圍；核對文件名稱／版本，僅查看、不核准、不發布。

②預期／通過：一般目錄不含未核准內容；審核目錄可供居督查看草稿 metadata，但居督沒有主任／admin 的核准權。數量記當次實際值，不沿用舊 16／22 筆作現況斷言。

③失敗／阻擋：未核准被標為已核准、一般入口漏出草稿記失敗；無權的文件操作顯示拒絕屬預期，不放寬權限。原始文件版本待提供時記阻擋。

## 步驟 5：居督自己的錄音及他人編輯拒絕（04-12）

①操作：如 S1 有自己的測試錄音，依 C1 手冊步驟10 標註並重開。再以預置隔離 T-A（屬 C1）做已核准的讀取／編輯負向對照；不嘗試修改正式錄音，不送未授權寫入。

②預期／通過：自己的標註可保留；別人的錄音不能因 supervisor 身分而編輯，拒絕／不提供入口是預期。未知說話者不被猜成固定角色。

③失敗／阻擋：只有 C1 錄音而無 S1 本人錄音，正向部分記阻擋，不能把無權限當整個功能壞掉。負向 API 測試可能留稽核，僅 C 環境進行。

## 步驟 6：私人歷程與工單分離（04-24）

①操作：由負責人提供隔離的「一般工單可見但未獲私人歷程授權」對照及已核准／未核准歷程對照，核對 S1／S2 所見。只讀既有授權，不申請、批准或撤銷權限。

②預期／通過：私人 interaction 歷程要符合明確授權，不以同機構、工單指派或職稱推定可看全部 QA／逐字稿。不同入口的查閱範圍另記，不能把 legacy QA 與 interaction 混用。

③失敗／阻擋：GET 歷程會留稽核，正式環境不可測；沒有適當對照記阻擋。若舊入口與新政策不同，記實際入口、代號與差異交嘉安確認，不擅改政策或宣稱已統一。
