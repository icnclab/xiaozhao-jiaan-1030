# 主任角色測試手冊（director）

更新：2026-11-07。主任不是系統管理員 admin；原手冊的建立帳號、正式產碼、文件發布與稽核查看已改為本輪安全門檻／正確角色配合。

先讀 [00 總覽](00_總覽與系統狀態.md) 的 A/B/C/X 門檻。以下互動項目均需 C 門檻，**本輪尚未執行**；在正式 8140／ltc_clean 不登入、不提問、不寫草稿。先用紙上演練（A）核對流程。實際結果統一填 [04 驗收表](04_驗收勾選表.md)，問題填 [05 問題表](05_問題回報表.md)。

## 步驟 0：環境、帳號與範圍確認（不計通過數）

①操作：填 00 的環境欄，對照現有 C1／S1／D1 三角色及必要 S2／C2／A1；請管理員協助確認受控綁定。不要建立帳號、產碼、改角色、改機構、解除綁定或重啟部署。

②預期／通過：有隔離測試網址／版本、非 ltc_clean 資料庫確認及通知隔離證據，角色能用既有帳號對應。

③失敗／阻擋：沒有隔離環境就停在文件演練。director 核發碼目前被路由拒絕是已知靜態落差，不換 admin 冒充主任完成測項。

## 步驟 1：主任本人 LINE 登入（04-3）

①操作：D1 用本人手機、既有受控綁定進隔離 LIFF；核對 director 及機構。若查看後台，用 D1 的現有登入方式，不能共用管理員 session。

②預期／通過：顯示主任工作台／director；不因顯示「主任」就忽略實際 role。

③失敗／阻擋：缺 director 身分／綁定記阻擋；錯配即停。登入會寫 session／稽核，正式環境不做。

## 步驟 2：人員查看及照服員後台拒絕（04-13、14）

①操作：D1 看同機構現有測試人員及角色，不更動。C1 於隔離測試下嘗試人員管理頁的讀取入口，觀察拒絕；不按建立／停用／刪除。

②預期／通過：D1 可看測試名單；C1 不取得管理內容，應導回登入／顯示無權限，API 可為 401／403，依是否已登入記錄。角色顯示與帳號一致。

③失敗／阻擋：C1 取得人員管理資料即嚴重失敗，立即停。沒有 C1／D1 對照則阻擋；前端藏連結不等於後端已驗收，要另記後端拒絕證據。

## 步驟 3：文件管理與來源核對（04-15）

①操作：D1 檢查自己沒有「知識庫文件」管理入口；隔離負向讀取 `/admin/documents`／相關 API 應受拒絕。如要核對文件清單，由現有有權 S1／A1 另用本人身分查看去識別化測試文件，不代登入、不發布或核准。

②預期／通過：主任不具有目前未授予的文件管理權；有權協作者可核對版本與來源狀態。一般 RAG 引用與文件管理是不同測項，舊 16 筆不是現況通過標準。

③失敗／阻擋：D1 被拒絕是預期，不記系統故障；協作者缺席則文件內容核對記阻擋。草稿冒稱正式、來源錯置等另記失敗。

## 步驟 4：BA／GA09／SC09 審核目錄（04-16）

①操作：D1 查看 `/admin/catalog` 對應審核 metadata，與嘉安提供的原始空白表單比對欄位、版本、必填、時間格式、簽章要求；不輸入真人資料、不按核准或修改範本。

②預期／通過：能區別待審與正式核准；一般目錄只公開已核准內容。記錄實際版本與差異，缺少來源不能判定表單規格通過。

③失敗／阻擋：沒有核准版原始表單記阻擋；不可為了讓表單顯示而把 reviewed 改 true。欄位差異記失敗／待確認，不自行修正資料。

## 步驟 5：稽核權限邊界與管理員配合（04-17）

①操作：D1 核對沒有 admin 專屬稽核入口；如需實際稽核證據，由 A1 在隔離環境用自己身分檢視本次測試事件代號，僅摘時間／動作／角色／結果，不匯出內容。

②預期／通過：D1 存取 admin 稽核 API 被拒絕屬通過；A1 才能檢視。若要驗記錄完整性，須把各操作實際留下的事件另行核對。

③失敗／阻擋：A1 未配合時只完成主任拒絕邊界，稽核內容完整性仍阻擋；不能把主任看不到稽核記成缺陷，也不能直接代用 A1 帳號。

## 步驟 6：緊急通報總覽與警語（04-18）

①操作：在 C 環境看已有虛構通報狀態／歷程，核對 D1 的同機構管理範圍及警語。只查看，禁止新增、接手、解除、通知重試、訂閱推播或觸發響鈴。

②預期／通過：列表與既有假資料狀態一致，清楚說明網頁提示不等於跨 APP／鎖屏送達；D1 的緊急管理角色不等於一般工單處理權。

③失敗／阻擋：沒有預置假通報則本項阻擋，不能為測試新增真實通報。背景通知、接手競爭、解除與離線備援本輪均未驗收。

## 步驟 7：測試紀錄交付（不操作資料清理）

①操作：將 04、05 補齊，列測試代號、時間、環境、實際結果及不含個資的證據名稱。只列將來可能需清理的隔離假資料代號。

②預期／通過：每項有通過／失敗／未執行／阻擋／不適用之一，問題可追溯，沒有把工程測試或畫面預覽算真人通過。

③失敗／阻擋：不確定是否假資料就記待確認，不刪除任何帳號、工單、錄音、備份或正式資料。

## 步驟 8：主任與 admin、一般工單處理權分離（04-23）

①操作：D1 在隔離環境核對案件監督、治理指標與人員查看；對照文件／回饋／分類設定及 admin healthz 應拒絕。一般工單接手、回覆／結案只看權限／紙上演練，不實際送出。

②預期／通過：D1 維持治理與監督範圍；一般工單處理 API 不授予 director。A1 的 technical／healthz 不代表可讀所有私人 interaction。前端與端點各自記錄。

③失敗／阻擋：D1 取得未授予權限、或 C1／S1 跨角色看到 admin 機密，立即停並回報。缺少可用負向資料記阻擋，不自行授權。

## 步驟 9：未核准表單與他人草稿保護（04-25）

①操作：使用隔離環境預置的未核准範本及他人草稿，先紙上核對；如已明確准許隔離負向 API 測試，才驗證既有未核准草稿不能正式送出、唯讀受權者不能改別人的草稿。不變更核准或授權狀態。

②預期／通過：未核准範本不在一般目錄，送出被拒絕；他人草稿不可修改／送出。D1／S1 能看 metadata 不等於可編輯私人服務紀錄。

③失敗／阻擋：無預置資料或未核准負向操作則阻擋；若可能意外成功寫入，只在隔離環境測，正式環境不送。被拒絕可為通過，不可為測試把範本改成正式。
