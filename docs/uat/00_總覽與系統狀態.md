## 三、角色權限（程式層確認，尚待真人 HTTP 驗收）

- 系統角色：`caregiver`（照服員）、`supervisor`（居督）、`admin`（主任／管理員）。
- 綁定機制：居督／主任可透過 `POST /api/admin/users/{user_id}/binding-code` 幫照服員或其他角色產生「LINE 綁定碼」，再由該使用者在 LIFF 內輸入綁定碼完成綁定（不需要先有 LINE 好友或帳密）。
- 本次 UAT **不自行建立真實嘉安同事帳號**；如需測試帳號，請由主任角色在正式系統內用**虛構姓名**建立測試帳號（見手冊「測試前準備」）。

## 五、UAT 安全限制（請所有測試者務必遵守）

1. **禁止使用任何真實長者、真實案主的姓名、病歷、電話或住址**，一律用虛構姓名（例如：王小明、測試案主01）。
2. **禁止送出真實緊急通報**：緊急通報功能只能在測試情境下操作到「填寫畫面」為止；若系統會真的推播/通知，請先向負責同學確認目前通知對象是否為測試帳號，否則**不要按下最終送出**。
3. 不要測試或嘗試繞過角色權限（例如用照服員帳號硬改網址存取主任功能）去新增真實資料；若是為了驗證「權限應該擋住」而故意嘗試，請在回報表記錄「預期會被拒絕」。
4. 測試中若看到任何疑似真實個資（不是你自己建立的虛構資料），**立即停止並回報負責同學**，不要繼續操作或截圖外流。
5. 測試產生的虛構資料（測試帳號、測試個案、測試表單）測試結束後由負責同學統一清除，測試者不要自行刪除資料。

## 七、建議測試順序

1. 主任先完成「測試前準備」：建立 3 個虛構測試帳號（照服員／居督／主任各 1，若正式環境已有測試帳號則沿用）、產生 3 組綁定碼。
2. 照服員角色測試（`01`）：LINE 綁定 → 文字提問 → 語音提問 → 轉人工情境 → 服務表單填寫。
3. 居督角色測試（`02`）：案件查看／回覆 → 跨居督共享（候選版）→ 審核通知。
4. 主任角色測試（`03`）：使用者管理 → 法規文件管理 → 服務分類審核 → 稽核紀錄查看 → 緊急通報總覽（不送出真實通報）。
5. 三人一起核對 `04_驗收勾選表.md`，有問題填 `05_問題回報表.md`。
