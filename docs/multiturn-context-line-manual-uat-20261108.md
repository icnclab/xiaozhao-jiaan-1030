# 本人 LINE 內部測試步驟（僅在 UAT 切換另獲授權並完成後使用）

## 前置確認

- 入口明確顯示 UAT／測試，使用既有「小照 UAT 測試機器人」，不要加入正式小照。
- 只用虛構人名、房號與事件；不要貼真實個案、錄音或訪談。
- UAT health、schema `0010_service_interactions`、frontend artifact commit、outbound blocked 均由維運者核對完成。
- 測試過程不啟用聊天 reply、推播、緊急通知或 Web Push。

## 操作與預期結果

1. 從 UAT LIFF 開啟「問 AI」，以文字輸入：「夜間每多少位住民要配置一名照服員？」
   - 預期：回答附出處；產生新的 conversation；不含其他歷史問題。
2. 回到「問 AI」直接再送：「那夜間呢？」但不要點上一題的「繼續提問」。
   - 預期：視為新對話，不應沿用上一題。
3. 回到第一題結果，點「繼續提問」，輸入：「那夜間呢？」
   - 預期：沿用同一 conversation，回答仍須有本輪 RAG 出處。
4. 快速重按或在網路短暫中斷後重試同一次送出。
   - 預期：回傳同一結果，不新增第二題或第二個案件。
5. 由測試操作頁結束該 Interaction；若目前 LIFF 尚未提供結束按鈕，請維運者用受控 UAT 測試工具執行，不直接操作 DB。
   - 預期：結束後新追問顯示對話已結束／無法繼續；重送結束前已完成的 request 仍回原結果。
6. 嘗試在 request 中加入 `case_id`／`case_context`（由測試工具執行）。
   - 預期：HTTP 422；不接受個案 Context。
7. 輸入虛構高風險句：「住民昏倒了沒有呼吸」。
   - 預期：不產生一般 RAG 回答，顯示緊急處置提示並轉督導；因 outbound blocked，不應收到 LINE 推播。
8. 以另一位已核准的 UAT 測試身分嘗試開啟第一位的 conversation URL／ID。
   - 預期：404／找不到資料，不揭露對話是否存在。
9. 使用 LIFF 語音入口說一段不含個資的規範問題，確認逐字稿後送出，再點「繼續提問」。
   - 預期：確認後文字進入同一問答流程；只有明確續問才帶 Context。

## 記錄方式

- 記錄時間、步驟編號、畫面結果、HTTP 狀態或錯誤碼；不要截入 userId、token、綁定碼或真實個資。
- 若出現跨帳號資料、錯誤引用、結束後仍可新增、通知外送或正式網址，立即停止測試並保留非敏感證據。
