# 多輪問答個案授權決策

## 範圍與狀態

- 已完成的多輪功能只延續同一使用者、同一機構、同一 `conversation_id` 的上一筆遮罩問題；一般規範問答仍可使用。
- 個案 Context **停用**：問答不載入案件、住民／服務對象資料、回答或逐字稿作為多輪 Context。
- 前端只送出已定義的問答欄位；後端 `AskIn` 拒絕未定義欄位，包含 `case_id` 與 `case_context`，以 HTTP 422 fail closed。
- 本次不變更資料庫、不新增授權欄位或 migration，也不執行部署。

## 授權判斷

現有 `cases` 表代表送交督導的案件，具有建立者、機構與指派督導等資訊；它沒有可靠的服務對象／個案識別關聯、授權主體與範圍、有效期限、撤銷狀態或個案資料存取稽核。因此，僅依角色、同機構、案件建立者或前端提供的 ID，不能證明使用者有權把該服務對象資料帶入模型 Context。

在授權資料模型與經核准的業務規則可被伺服器端驗證前，不提供個案 Context 的請求欄位或資料查詢路徑。不得把問答案件（escalation case）當成照護個案授權。

## 目前安全邊界

1. 多輪查詢只讀 `qa_items.question_masked`，並以使用者、機構及對話 ID 限定；查詢不連接 `cases`。
2. 對話不存在或不屬於目前使用者／機構時，既有 API 以不洩漏資源存在性的 404 拒絕。
3. 不接受未定義的問答請求欄位；LIFF 導覽狀態中的個案 ID／Context 不會進入問答 API。
4. 一般規範問答、來源檢索與高風險攔截維持原有流程。

## 未來啟用前置條件（目前未實作）

- 經核准的服務對象資料模型及明確關聯，不以使用者傳入的 ID 作為授權依據。
- 伺服器端逐次驗證使用者、機構、職務／照護關係、授權範圍、有效期及撤銷狀態；無法判定即拒絕。
- 授權核發、撤銷、拒絕及資料存取具可稽核紀錄，並有最小必要資料與保存期限規則。
- 以 Mock 測試覆蓋跨機構、非照護關係、過期／撤銷授權、角色變更、偽造 ID、重放與撤銷後存取；再經核准的 HTTP 驗收及真人操作驗收。
